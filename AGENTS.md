# AI Novel Studio engine operating contract

This repository contains a reusable continuity engine and separate story datasets. Read `docs/ENGINE_READINESS.md` for unmet acceptance gates, `docs/POSTMERGE_PROPOSALS.md` for metadata-only automation, `ENGINE_E7.md` for onboarding, `ENGINE_E6.md` for synthetic acceptance, `ENGINE_E5.md` for bounded provenance/ledger proposals, and `ENGINE_E3_E4.md` plus `docs/AGENT_RUNBOOK.md` for local workflow. `ENGINE_E2.md` defines schema/replay and `ENGINE_E1.md` story-root compatibility. Read the selected story's `AGENTS.md`, `story.json`, canon, rules, style, and state before touching its data. Story instructions apply only inside their story root.

- Core code lives in `scripts/`; story data, rules, styles, research, and prose live in `stories/<slug>/`.
- `studio.json` selects the default story for legacy CLI commands. Always pass an explicit story when working across datasets. Never fall back to another story after a missing reference or file.
- LOCKED human decisions take precedence over suggestions. Planned beats, draft prose, and structural validation do not establish approved history. UNKNOWN remains unknown.
- Do not change story content, promote canon, fabricate provenance, approve prose, or merge without the human user's explicit authorization for that action.
- Engine-only tasks must use synthetic metadata fixtures for new scenarios; do not write narrative prose.
- Scope changes to a feature branch. Reuse the existing validators and pack builder; do not add paid APIs, credentials, databases, or unrelated services.
- Use Python 3.11+ and install the pinned schema dependencies first with `python -m pip install --index-url https://pypi.org/simple --only-binary=:all: -r requirements.txt`. E2 is no longer stdlib-only. Schema validation uses the real Draft 2020-12 validator and local schema resources; do not fetch story-supplied remote schemas.
- Local review/Git diagnostics require a Git version supporting the global `--no-lazy-fetch` option. Unsupported Git must fail review or leave Git diagnostics UNKNOWN; do not fetch missing objects, install Git, or change persistent Git settings to hide the limitation.
- Run `python scripts/novelctl.py check`, `python scripts/story_engine.py check`, and `python -m unittest discover -s tests -v`. Verify legacy commands, story selection, replay boundaries, and preservation of example bytes when changing engine behavior.
- Optional state history replays only eligible local evidence strictly before the target. Incomplete explicit history stays UNKNOWN; with no history file, retain the documented legacy snapshot/UNKNOWN path. Never synthesize deltas from planned effects. Local APPROVED labels and fixture evidence are not authenticated GitHub human approval. E5 observes bounded live merge/source facts only; human editorial approval remains UNVERIFIED.
- The opt-in S1 world model is documented in `docs/WORLD_STATE_S1_TH.md`. `data/world_model.json` declares source-bound observations, positions, holders, containment and explicit world coordinates; `check` validates it only when `story.json.world_state.enabled` is true. It is separate from v1 history: never use array order or narrative order as world chronology, apply observations as deltas, infer omitted facts, or claim a world-state projection/query exists. Preserve original IDs and bytes; ASCII IDs apply only to new tracked references, with localized names/aliases separate. Matching source hashes and local labels do not authenticate human approval.
- Scope every writer, reviewer, and updater handoff to one explicit story root, target, and real commit/base anchors. A local review bundle describes the current working draft, which may differ from HEAD; use its draft digest and diff rather than claiming it is committed or reviewed. Machine output is advisory and never promotes canon.
- Keep review bundles and diagnostics local. New `brief-review`, `doctor`, `verify-provenance`, and `rollup` file output is restricted to the selected workspace's ignored `.local/` directory. Bundles can contain unpublished prose and full context; do not attach them to a public PR or send them externally without explicit user authorization.
- `brief-review` prepares local evidence, `propose` aliases `proposal`, and `doctor` reports local checks. They do not run a model, authenticate GitHub approval, verify repository settings or CODEOWNERS enforcement, or perform rollup. Preserve UNKNOWN for checks that were not performed.
- `verify-provenance` performs explicit read-only GitHub checks using existing `gh` authentication; it never logs in, creates credentials, or changes settings. Offline evidence remains OFFLINE_UNVERIFIED even when internally consistent. Live merged metadata/source hashes are not proof of human editorial approval. Inaccessible or inconsistent evidence fails closed; never infer approval from merged_by, account type, or a local APPROVED field.
- `rollup` makes a deterministic concatenation proposal from eligible local approved ledger recaps. Its default is offline with UNVERIFIED_LOCAL_DECLARATIONS; `--verify-remote` explicitly checks each record's repository/PR/head/merge/source hash. It never applies the proposal or updates canon, ledger, or state.
- The postmerge workflow creates a metadata-only PROPOSED artifact after verifying an eligible continuity push-to-main run and matching merged PR identities. It executes inline stdlib code from the installed default-branch workflow, never checked-out PR/merged source, dependencies, caches or upstream artifacts. Keep token permissions read-only, upload only the fixed proposal JSON, and preserve human editorial approval as UNVERIFIED. Live trigger remains NOT_RUN until owner-authorized installation/merge; do not merge to manufacture test evidence.
- Preserve existing regression coverage (228 tests at E6/E7) and all 54 original example files against the byte-integrity manifest; add synthetic metadata tests without weakening earlier assertions.
- `python scripts/acceptance.py --out .local/<new-run>` exercises real CLI commands in a fresh synthetic workspace. Its local Git anchor and APPROVED labels are fixtures, never human signoff. It performs no semantic review. Keep recorded key/packet/raw-report bytes intact; CI integrity checks do not rerun the independent reviewer. Do not claim overall E0–E7 completion while readiness gates remain unmet.
- Draft PRs must report actual tests, remaining limits, changed files, and exact head/CI. Do not claim a complete engine from one milestone.

The Last Island example retains its original contract under `stories/last-island/AGENTS.md`. Its existing content is preserved; moving files does not approve any narrative or canon changes.
