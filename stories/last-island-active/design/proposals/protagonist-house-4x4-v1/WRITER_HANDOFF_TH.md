# เป้าหมายขยายบ้านตัวเอก 4×4 สองชั้น — ยังไม่ใช่สภาพที่สร้างแล้ว

บันทึกคำสั่งออกแบบของผู้เขียนสำหรับบ้านอ้างอิง `LOC-009` / ตัวเอก `CHAR-001` โดยใช้ proposal template และ writer card เดิม **สถานะ PROPOSED / target only** ไม่มีฉากเริ่มสร้าง ฉากเสร็จ หรือหลักฐานว่าต่อเติมใช้งานแล้ว การบันทึกเข้า repository ไม่ได้อนุมัติ canon หรือ ledger

อ่าน [target_v01.json](./target_v01.json) สำหรับแบบเป้าหมายและคำพูดต้นฉบับครบ พร้อมรหัสข้อความที่ได้รับในงานนี้ และ [writer_reference_card.json](./writer_reference_card.json) สำหรับการส่งต่อให้นักเขียน ทั้งสองเป็นเอกสารให้คนอ่าน ไม่ใช่ schema/input ที่ engine โหลดอัตโนมัติ

| ผู้เขียนกำหนดเป้าหมายแล้ว | ยังไม่ทราบ / ห้ามเติมเอง |
|---|---|
| ขนาดรวม 4×4 สองชั้น เก็บบ้าน 2×2 ไว้ด้านใน มีกรอบรอบนอกหนึ่งกรอบ | เมตรจริง จำนวนชิ้นพื้น พิกัด/ระยะเยื้องของแกนบ้าน ความกว้างกรอบและช่องเปิด |
| แนวกำแพงด้านข้างรวม **สองแนว**: ขอบนอก 4×4 และกำแพงบ้านเดิม 2×2 | ไม่มีแนวที่สาม และไม่ใช่เพิ่มอีกสองชั้นจากกำแพงเดิม |
| ด้านบน “ทำแบบเดียวกัน” ตามถ้อยคำผู้เขียน | ภาพตัด จำนวน/หน้าที่ของแผ่นพื้น เพดาน หลังคา ความสูงและโครงสร้างรองรับ |
| ขอบชั้น 2 เป็นพื้นที่ชั้นยิง มีกำแพงเตี้ยรอบ | แผนห้อง ประตู บันได ทางเดิน รายละเอียดรอยต่อของกำแพงเตี้ยกับแนวป้องกันแกนบ้าน |
| เสาหลักกลางบ้านหนึ่งต้นสำหรับทั้งหลัง | พิกัดจริง เกณฑ์วัดศูนย์กลาง อิทธิพล ความสูง และวิธีย้ายเสา |

ลำดับเชิงความสัมพันธ์ของแนวกำแพงคือ:

```text
ภายนอก → กำแพงขอบ 4×4 → พื้นที่กรอบรอบนอก → กำแพง 2×2 เดิม → ห้องด้านใน
             แนวที่ 1                              แนวที่ 2
```

นี่คือการผ่านแนวกำแพง **สองแนวทั้งหมด** จึงถึงห้องใน ไม่ใช่เส้นทางประตูที่เดินผ่านได้ และไม่ใช่จำนวนระเบิด กระสุน หรือครั้งโจมตี ไม่คำนวณค่าแข็งแกร่งสะสม ความทนทาน การเจาะ หรือเส้นทางโจมตีที่เหมาะที่สุด กำแพงเตี้ยรอบพื้นที่ยิงชั้น 2 บอกหน้าที่ของขอบพื้นที่นั้น แยกจากชั้นป้องกันของบ้านด้านใน ไม่เพิ่มเป็นแนวป้องกันที่สาม

## ส่งต่อให้นักเขียนอย่างไร

1. ถ้าเขียนฉากที่ยังไม่ได้สร้าง ให้เรียกการ์ดสภาพบ้านตามฉากเดิม ไม่ใช้ target นี้แทนบ้านในฉาก เช่น:

   ```bash
   python scripts/storyctl.py --story last-island-active house-card LOC-009 --scene SC-047 --boundary AFTER --source-mode committed --out .local/house-sc047.json
   ```

   การ์ดนั้นยังเป็นบ้านเดิม 2×2 กับการคิดเสริมป้องกันที่ยังไม่ได้สร้างใน EP-005 ขอบเขตของข้อมูลเป็นของฉากนั้น ไม่ใช่ข้อสรุปทุกเวลา ถ้าไม่มี exact view ของฉากที่ต้องการ ให้ UNKNOWN ไม่ยืมภาพปลายบทหรือ target ในอนาคตมาแทน
2. ถ้าจะวางแผนฉากขยาย ให้ส่ง target `TARGET-4X4-V01` พร้อมรายการ UNKNOWN ให้นักเขียนในฐานะ **เป้าหมายจากผู้เขียน** ต้องขอรายละเอียดฉาก/เวลาสร้าง วัสดุ ประตู บันได และการเปิดใช้งานเพิ่มเติมก่อนบรรยายว่าเกิดขึ้นแล้ว
3. แยกความรู้ของผู้เขียนเรื่องแบบเป้าหมาย ออกจากความรู้ POV ของตัวละคร การ์ดนี้ยังให้ POV knowledge, world construction time และ narrative reveal เป็น UNKNOWN ไม่มีการเพิ่มความรู้ให้ตัวเอกหรือศัตรูอัตโนมัติ
4. เมื่อต่อเติมเกิดขึ้นในต้นฉบับที่ผ่านขั้นตอน review ภายหลัง ค่อยเสนอข้อมูลสภาพบ้านตามฉากพร้อมแหล่งอ้างอิง โดยเก็บประวัติบ้านเก่าไว้ ห้ามแก้ snapshot เก่าหรือเลื่อนเวลาเสร็จย้อนกลับจาก blueprint

กลุ่มเจ้าของ จำนวนประตู เส้นทางบันได วัสดุ เวลาสร้าง ความสูงและค่าพลังป้องกันยัง UNKNOWN ไม่ได้ผูกกับ archetype ทั้งแปดใน House Atlas ไม่มีภาพตัดที่ยืนยันได้ และไม่มีคำรับรองด้าน gameplay หรือวิศวกรรม

## ขอบเขตข้อมูลและการตรวจ

เอกสารนี้คัดลอกจาก [proposal scaffold เดิม](../house-atlas-v1/house_template_proposed.json) และ [ส่วน template ของ writer card เดิม](../house-atlas-v1/writer_reference_card.json) เป็นรุ่น target ใหม่ ไม่แก้ pilot workshop หรือ reference สามชั้นแบบสมมติของ Atlas เดิม เพราะเป็นคนละแบบ ไม่เปลี่ยน `data/house_references.json`, timeline, manuscript, canon, memory หรือ ledger

ตรวจ JSON syntax, ความสอดคล้องของรหัส target/card, แนวกำแพงสองแนวและลิงก์อ้างอิงได้ แต่ไม่มี registered schema ของ target ชนิดนี้ จึงไม่เรียกผลตรวจว่า engine-schema PASS หรือ geometry/gameplay PASS ส่วน regression CI ตรวจ engine เดิมตามปกติ โดยไม่รับรองว่าบ้านนี้สร้างแล้ว
