# คู่มืออ้างอิงบ้านสำหรับนักเขียน

แพ็กเกจนี้เป็น **เอกสารช่วยเขียนสถานะ PROPOSED** ไม่ใช่บ้านที่รับรองแล้วหรือ canon ให้ตอบว่า “ยังไม่มีข้อมูลยืนยัน” เมื่อหลักฐานของฉากไม่พอ

## เริ่มค้นข้อมูล

1. ระบุขอบเขตคำถาม: ฉากจริงของ Last Island หรือ fixture สังเคราะห์ที่ทำเครื่องหมาย `SYNTHETIC-NOT-STORY` ชัดเจน ห้ามนำ fixture ไปผูกกับฉากจริง
2. อ่าน [house_template_proposed.json](./house_template_proposed.json), [archetype_programs.json](./archetype_programs.json), [pilot_workshop_versions.json](./pilot_workshop_versions.json) และ [construction_stages.json](./construction_stages.json) ตามต้องใช้
3. ตรวจสถานะ adoption จากข้อมูลที่ระบุชัดในแพ็กเกจเท่านั้น ขณะเขียนคู่มือนี้ไม่พบ record ที่ระบุ `ADOPTED`; template, แบบทั้ง 8 archetype, pilot ทั้ง V01–V03 และ timeline เป็น `PROPOSED` ไม่มีการค้นประวัติสนทนาส่วนตัว
4. เปิด [writer_reference_card.json](./writer_reference_card.json) เป็นแบบฟอร์มเพื่อแยกแบบพิมพ์เขียว สภาพก่อสร้าง การใช้งาน และความรู้ของ POV

## ระดับหลักฐาน

- **ทิศทางที่ผู้ใช้ยืนยัน:** ใช้โมดูลสี่เหลี่ยมกับสามเหลี่ยมประกอบได้หลายแบบ และกำหนดเสาหลักหนึ่งต้นไว้กลางบ้านทั้งหลัง ผู้ใช้ต้องการให้จดจำบ้านตามผู้เล่นหรือกลุ่ม แต่ตัวตนและการผูกบ้านกับคนยังไม่ระบุ
- **ข้อเสนอ:** ทุกโปรแกรม ห้อง รูปทรง ตำแหน่ง ทางเดิน เส้นเวลา synthetic และการเปลี่ยน V01 → V02 → V03 เป็นข้อเสนอเท่านั้น แบบใน pilot ใช้ `ILLUSTRATIVE_GRID_V1`; จุดกึ่งกลางคำนวณด้วย centroid ของพื้นที่ชั้นล่างเพื่อการวาด ไม่ใช่กฎในเกม
- **UNKNOWN:** ไม่มีข้อมูลยืนยันว่าเวอร์ชันใดตรงกับฉากจริง เวลาในโลกเรื่องหรือเวลาที่ผู้อ่านเห็น การเป็นเจ้าของ ผู้พักอาศัย ที่ตั้ง สภาพอาคาร การซ่อม ความเสียหาย มิติจริง ความสูง การรับน้ำหนัก กฎบันได และผลของเสาหลัก
- **ความรู้ POV:** ผังจริงของข้อเสนอไม่แปลว่าตัวละครรู้ผังนั้น บันทึกห้องหรือเส้นทางที่ POV รู้ได้เฉพาะเมื่อมีหลักฐานในฉาก; หากไม่มีหลักฐานให้คง `UNKNOWN` และรายการห้อง/เส้นทางที่รู้เป็นว่าง

## วิธีทำบัตรอ้างอิงต่อฉาก

1. คง `house_id` เดิมเมื่ออ้างถึงบ้านหลังเดิม; ระบุ `version_id` แยกจาก ID บ้าน ห้ามรวมรุ่นหรือสร้างชื่อเจ้าของขึ้นเอง
2. ระบุ **target blueprint** ว่ากำลังเทียบกับแบบใด แล้วระบุ **as-built snapshot** ณ เวลาสร้างในฉากแยกกัน การมีแบบไม่ได้แปลว่าสร้างครบ
3. แยกนาฬิกาสามชุด: เวลาก่อสร้างในโลกเรื่อง, ลำดับ/เวลาที่เรื่องเปิดเผยข้อมูล และความรู้ของ POV อย่าคำนวณหรือเทียบกันหากต้นทางไม่ได้ระบุ
4. กรอกสถานะ **รายส่วน** เป็น `PROPOSED`, `NOT_BUILT`, `IN_PROGRESS`, `COMPLETED` หรือ `UNKNOWN`; usability ใช้ `AVAILABLE_IF_SCENE_EVIDENCED`, `AVAILABLE_IN_SYNTHETIC_PLAN`, `UNAVAILABLE` หรือ `UNKNOWN` ตามบัตร ใช้ค่า synthetic เฉพาะ fixture เท่านั้น การเสร็จของชิ้นส่วนไม่รับรองว่าห้องหรือทางเดินเปิดใช้ได้
5. บันทึกห้อง ประตู ช่องเปิด ทางเดิน และบันไดด้วย ID จากเวอร์ชันเดียวกัน ไล่เส้นทางผ่าน ID จริง ถ้าขาดประตูหรือทางเชื่อมอย่าเติมทางลัดหรือ teleport เอง บันไดใน pilot เป็นเส้นทางเชิง topology และความเป็นไปได้ทางกายภาพยัง `UNKNOWN`
6. วางเสาหลักหนึ่ง ID ต่อบ้านทั้งหลังในบัตร ไม่ทำสำเนาตามชั้นหรือเวอร์ชัน ตำแหน่ง `[0,0]` และ centroid เป็นเพียง convention ของภาพ ขนาด อิทธิพล การย้าย และหน้าที่จริงยัง `UNKNOWN`
7. ความเสียหายและการซ่อมบันทึกเฉพาะหลักฐานชัดเจน หากไม่มีให้ใช้ `UNKNOWN`; ห้ามอนุมานสภาพสมบูรณ์จากการที่ห้องใช้งานได้
8. แนบภาพให้ตรงรุ่น: [WORKSHOP-V01.svg](./diagrams/WORKSHOP-V01.svg), [WORKSHOP-V02.svg](./diagrams/WORKSHOP-V02.svg), [WORKSHOP-V03.svg](./diagrams/WORKSHOP-V03.svg) เป็นภาพข้อเสนอของ pilot; [MAKER.svg](./diagrams/MAKER.svg) เป็นแนวคิด archetype ที่ยังไม่วางพิกัด ห้ามใช้ภาพวิจัยแทนผังบ้านในเรื่อง
9. หากไม่พบ record ที่รับรอง อย่าเปลี่ยน `PROPOSED` เป็น `ADOPTED` และอย่าเรียกบ้านนี้ว่าบ้านที่ตัวละครมีจริง

## ชั้นป้องกันรอบบ้านและประตูหลายชั้น

เมื่อฉากเกี่ยวข้องกับชั้นป้องกัน ให้อ่าน [บัตรและตัวอย่างแยก](./defensive_envelope_reference.json) กับ [คำแนะนำ](./DEFENSIVE_ENVELOPE_WRITER_TH.md) ก่อนเขียน บ้านชั้นในไม่ใช่ชั้นป้องกัน: เลือก ID ของผนังแต่ละด้าน ชั้นด้านบน และประตูเรียงตามทางเดินที่มี ณ ฉากนั้น ตรวจการสร้าง/เปิดใช้/ความเสียหายแยกชิ้น ห้ามให้ชั้นถัดไปหรือประตูอื่นหายตามเมื่อชั้นหนึ่งถูกระบุว่าเสียหายหรือมีช่องเปิด

จำนวนชั้นเพิ่มได้ตามข้อมูลเรื่อง แต่ไม่ใช่ตารางอัปเกรดอัตโนมัติหรือสูตรเพิ่มความแข็งแกร่ง ความหนาทางเรขาคณิต จำนวนชั้น วัสดุ และระดับความแข็งแกร่งในเกมต้องแยกช่อง ผู้ใช้ยืนยันว่าคำว่า “เท่ากัน” หมายถึงระดับความแข็งแกร่ง ไม่ใช่ความหนาจริง คู่เทียบประตูเหล็ก–ประตูหินเก็บตามคำเดิมและรอคำยืนยันตัวเปรียบเทียบ ห้ามเปลี่ยนเป็นกำแพงหินเอง ไม่เติม HP ค่าใช้จ่าย จำนวนวัตถุระเบิด หรือสูตรความเสียหาย ความรู้ POV ต่อชั้นที่ซ่อนอยู่ยัง UNKNOWN หากไม่มีหลักฐาน

## เส้นทาง pilot ที่อ่านได้จาก ID จริง

ใน V02 ข้อเสนอมีเส้นทาง `ภายนอก → DOOR-ENTRY → ROOM-ENTRY` ที่ชั้น 0, tile ขอบทางเข้า `TILE-G-SE`; จากห้องนั้น `STAIR-EXT-E` เชื่อม `LANDING-STAIR-F0`/`VOID-STAIR-F0` กับ `LANDING-STAIR-F1`/`VOID-STAIR-F1` และไปถึง `ROOM-MEZZANINE` ชั้น 1. `DOOR-WORKSHOP` เชื่อม `ROOM-ENTRY` กับ `ROOM-WORKSHOP` ผ่าน `EDGE-TILE-G-NW--TILE-G-SW`. นี่คือการอ่าน topology ใน pilot ไม่ใช่การยืนยันว่าตัวละครเดินได้จริง

ใน fixture `SYN-SC-B` เส้นทางชั้นบนนี้ยังไม่พร้อม: มีเพียง `ROOM-CORE` และ `DOOR-ENTRY`. ที่ `SYN-SC-C` ให้ใช้แบบ V02 และ fixture ระบุว่า `STAIR-EXT-E`, `DOOR-WORKSHOP`, `ROOM-MEZZANINE` เปิดใช้ในแผนหลัง event `OPEN-011`. อย่าย้อนใช้ห้องหรือบันไดชั้นบนกับฉากก่อนหน้า

## ขอบเขตของตัวอย่าง

`SYN-SC-A`, `SYN-SC-B` และ `SYN-SC-C` เป็นตัวอย่างดึงข้อมูลสังเคราะห์จาก `construction_stages.json` เท่านั้น: world tick 10, 30 และ 50 ตามลำดับ ไม่ใช่เวลา ฉาก หรือเหตุการณ์ของนิยาย ไม่มีระยะเวลาต่อ tick, เวลาเปิดเผยในเรื่อง หรือ POV ที่ยืนยันไว้ สถานะ usability ใน fixture หมายถึง `AVAILABLE_IN_SYNTHETIC_PLAN` เท่านั้น ไม่ใช่ข้อพิสูจน์กลไกเกมหรือความเป็นไปได้ทางวิศวกรรม

ทั้ง 8 archetype (`STARTER`, `MAKER`, `COMMUNAL`, `EXCHANGE`, `ARCHIVE`, `REST`, `GARDEN`, `REUSE`) เป็นโปรแกรมเสนอแบบไม่วางพิกัด เจ้าของและกลุ่มยังว่าง ไม่มีประวัติบ้านเดิมที่อนุญาตให้เติมเอง; ไฟล์ diagram ที่มีเป็นแนวคิด archetype ไม่ใช่หลักฐานของฉากจริง
